# Sakkan Properties AI Concierge

## Architecture

Broker -> Chainlit -> LangGraph -> Triage -> Property Finder -> Mortgage Analyst -> Communication -> Human Approval -> Broker. Property Finder uses Qdrant RAG plus listing tools. Mortgage uses an MCP calculator. mem0 is scoped by client ID. structlog records one trace ID across the request.

## Agent Roles

Triage identifies request intent. Property Finder combines semantic retrieval with deterministic listing filters. Mortgage Analyst calculates loan figures. Communication drafts only from supplied facts and listing IDs.

## RAG and Memory

The corpus contains 60 short documents. Gemini embeddings are stored in Qdrant. Retrieval returns document IDs and text. Memory is scoped to client IDs and writes require explicit consent. `/forget` deletes the scoped memory without exposing its contents.

## Human Approval

Every client-facing draft pauses for Approve, Reject or Edit. No draft is returned as a client message without approval.

## Evaluation

The test suite checks listing provenance, tool presence, provenance and HiL requirements. `outputs/eval_report.json` is generated by the test run.

## Limitations

The project uses a small fictional corpus and deterministic local tools. Production deployment would require authentication, stronger access control, audit retention policy and a real scheduling backend.

## Responsible AI

The system refuses to invent listings or prices, exposes uncertainty, scopes client memory, requires consent for memory writes and requires broker approval for every client-facing message.
